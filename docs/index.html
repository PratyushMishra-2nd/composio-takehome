100 apps, one agent: what it takes to turn an app into an agent toolkit

An agent researched auth, access gates, API surface and MCP coverage for 100 apps, citing a verbatim quote for every answer. Non-LLM checks, targeted re-research, a browser-use loop and a hand-checked 20-app sample measured how far to trust it, including one loop that made things worse and was rolled back.

The agent what it does, where a human was needed

A pipeline, not a chat. Every step writes files you can inspect in the repo, and every claim carries a verbatim quote and its URL, so another program can check it.

1 · App list100 apps scraped from the brief into data/apps.csv
2 · Research workersOne headless Claude Code worker per app (claude -p, Sonnet, 6 in parallel) with WebSearch + WebFetch. Output is forced into a JSON schema; every field needs a quote and a URL.
3 · Verifier (no LLM)Re-fetches every cited page and checks the quote is really there; checks auth against APIs.guru OpenAPI specs, MCP claims against the official MCP registry, and buildability against Composio's own toolkit catalog; checks for contradictions. Pages a plain fetch can't read are re-rendered in headless Chromium (browser-use loop).
4 · Targeted re-researchApps with any failed check go back to a worker with the exact disputes listed, then get verified again (2 rounds).
5 · Hand-checked sample20 apps (2 per category, seed 42) drafted blind by a different model, then hand-checked by Pratyush against vendor docs. It scores pass 1 and the final pass; its error classes became new verifier rules for all 100.
6 · Composio catalog checkEvery app is searched in Composio's tool router over MCP to find out whether a toolkit already exists. This yields the gap backlog.
7 · Approval trackerFor each gated app, the agent opens a GitHub issue through Composio's GitHub toolkit, so the follow-up queue exists from the moment research ends.
8 · Buildbuild.py merges everything into data.json, which this page renders.

Run it

git clone https://github.com/PratyushMishra-2nd/composio-takehome && cd composio-takehome
python agent/research.py --pass pass1            # 100 workers (needs Claude Code CLI logged in)
python agent/verify.py   --pass pass1            # independent checks -> results/redo_pass1.json
python agent/research.py --pass pass2 --redo results/redo_pass1.json
python agent/verify.py   --pass final            # round 2 checks; then pass3 on results/redo_pass2.json
python agent/verify_browser.py && python agent/verify.py --pass final   # browser-use loop
python agent/score.py && python agent/adjudicate.py   # vs data/gold.csv (blind model reference, reviewed by Pratyush)
python agent/enrich.py && python agent/verify_extras.py # webhooks, sandbox, rate limits, SDKs, spec
python agent/composio_catalog.py --all && python agent/outreach.py   # Composio MCP steps
python agent/build.py                            # corrections + docs/data.json -> this page

Single app: python agent/research.py --pass try --ids 61. The research step uses the Claude Code CLI's own login and the verification sources are public. The Composio steps need COMPOSIO_API_KEY in .env. Research uses real model usage (100 apps × several passes); verify, score and build run offline from the committed results and reproduce every number on this page. Full steps are in the README.
